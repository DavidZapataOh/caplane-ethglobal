--- what the two refusals above actually prove -------------------------------

The identity refusal is ours: a call to an address with no code returns `0x`, which is
indistinguishable from a registry holding nothing, so the frozen workflow name is read rather than
assumed.

The disagreement refusal is NOT ours — that message comes from viem, which rejects the foreign
chain before the two answers are ever compared. It still proves both endpoints are asked, because
a read using only the first would have succeeded. The comparison itself is exercised separately,
in `client.test.ts`, by handing the seam a real function whose answer depends on which endpoint it
received; and a second test pins that the comparison survives a bigint, because a lien carries
three and the obvious comparator throws on the first real read.

--- the package contacts nobody of ours -------------------------------------

The only hosts in the run above are the two RPC endpoints, both the caller's to change. A test
walks every module in `src/` for a hostname of ours and finds none; it assembles the needle from
pieces rather than spelling it, because spelled out the needle is in the test file and the walk
reports itself.

Switching off api.caplane.xyz, mcp.caplane.xyz and registry.caplane.xyz therefore cannot change any
line above. That run belongs to the rehearsal, which owns the outage window: the same process also
carries debtor confirmation.

--- what 0.1.0 cost, and why 0.1.1 exists ------------------------------------

0.1.0 shipped with viem pinned at 2.34.0, matching the rest of the repository. Measured on a fresh
install, `npm audit` then reported three advisories, two of them high:

  ws  uninitialized memory disclosure       GHSA-58qx-3vcg-4xpx   >=8.0.0 <8.20.1
  ws  memory exhaustion from tiny fragments GHSA-96hv-2xvq-fx4p   >=8.0.0 <8.21.0

`ws` is viem's WebSocket transport dependency. This package never constructs one — every read goes
over `http()` — so the vulnerable code is unreachable from here. `npm audit` cannot know that, and a
reader's first command printing "1 high severity vulnerability" costs more than the fix did.

viem carries the patched `ws` in its recent releases and the exact pin was the obstacle, so this
package takes a range where the rest of the repository keeps its pin. The two cases are different:
the copy vendored into the enclave has to behave byte for byte, while a package somebody installs
should dedupe against what they already have and receive security patches without waiting for us to
cut a release. Bumping it in the four other packages the night before a deadline — one of which
compiles into WASM — is the change that breaks something subtle, so it was made here and nowhere
else. The suite is what makes that safe: 26 tests against the live registry, green on the new
version before it was published.

Result on a fresh install of 0.1.1: `found 0 vulnerabilities`.
