What an agent can tell apart, and how it checks without us. Measured 2026-09-12.

The acceptance is not a tools/list that answers: a server that returned "not encumbered" for
everything would answer identically today, because the only lien the registry holds is released.
The divergence lives in the status and in the seven fields of the lien.

--- the same tool, two real ids ----------------------------------------------
  a lien the registry wrote — 0xebd60de9…
    encumbered  false
    status      released
  a submission it refused — 0x9c22eff8…
    encumbered  false
    status      none

The boolean is the same for both. It is not a bug and it is not hidden: encumbered is status exactly
active, and a released lien and an id nobody ever wrote are both not-active. The instructions the
server sends at initialize say so, so an agent learns it from the protocol rather than from a README
it will never fetch.

--- what this does not prove -------------------------------------------------

That the receivable exists, that the lien is fair, or that this server is honest. The receipt is
what makes the last one unnecessary: an agent replays every call against any node and compares
bytes, which is what the replay above does from outside the process.

It is still us in the middle. The defensible claim is the dossier's own §19.4 — demonstrably
dispensable — and not §20.3's "without us in the middle", which is false for this surface.
